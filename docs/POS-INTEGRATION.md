# คู่มือเชื่อมต่อ POS เดิมของร้าน

Smart Cam Sale รับยอดขายจาก POS ภายนอกผ่าน REST API — POS ยี่ห้อไหนก็ได้ที่ยิง HTTP ออกได้
(หรือเขียน middleware/plugin เล็ก ๆ คั่นให้) ยอดที่ส่งเข้ามาจะกลายเป็นประวัติซื้อของสมาชิก
คิดแต้มอัตโนมัติ (1 แต้ม/10 บาท) และไปโผล่ในคำแนะนำสินค้าตอนลูกค้าคนนั้นกลับมาที่ร้าน

## 1. สร้าง API key

หน้าเว็บ console → login ด้วยบัญชี **admin** → ปุ่ม **หลังบ้าน** → แท็บ **เชื่อม POS** →
ตั้งชื่อ (เช่นชื่อสาขา) + รหัสสาขา → **สร้าง API key**

> ⚠️ key แสดงครั้งเดียว — ระบบเก็บเฉพาะ hash คัดลอกเก็บทันที ทำหายต้องสร้างใหม่

## 2. ทดสอบการเชื่อมต่อ

```bash
curl -s https://<API_URL>/pos/ping -H "x-api-key: pos_xxxxxxxx"
# → {"ok":true,"name":"POS สาขาลาดพร้าว","storeCode":"main"}
```

## 3. ส่งยอดขาย

ยิงทุกครั้งที่ปิดบิล (หรือ batch ย้อนหลังก็ได้ — ระบบไม่สนใจลำดับเวลา):

```bash
curl -s -X POST https://<API_URL>/pos/sales \
  -H "x-api-key: pos_xxxxxxxx" \
  -H "Content-Type: application/json" \
  -d '{
    "memberPhone": "0812345678",
    "externalId": "RCPT-2026-08-0042",
    "items": [
      { "barcode": "8850999320014", "name": "น้ำดื่ม 600ml", "price": 10, "qty": 2 },
      { "barcode": "8850123456789", "name": "ลาเต้เย็น", "price": 45, "qty": 1 }
    ]
  }'
```

### Request fields

| field | จำเป็น | ความหมาย |
|---|---|---|
| `memberPhone` | อย่างใดอย่างหนึ่ง | เบอร์โทรที่ลูกค้าลงทะเบียนสมาชิกไว้ (วิธีหลัก — POS ส่วนใหญ่มีช่องเบอร์สมาชิกอยู่แล้ว) |
| `memberId` | อย่างใดอย่างหนึ่ง | id สมาชิกในระบบเรา (กรณี POS เก็บ id เราไว้) |
| `items[].barcode` | ✓ (หรือ productId) | barcode สินค้า — จับคู่กับ SKU ในแค็ตตาล็อก |
| `items[].qty` | ✓ | จำนวน 1–99 |
| `items[].name`, `items[].price` | แนะนำ | ถ้า barcode ไม่รู้จัก ระบบใช้สองตัวนี้**สร้างสินค้าให้อัตโนมัติ** (หมวด `pos_import`) — แค็ตตาล็อกจึงค่อย ๆ ครบเองจากข้อมูลขายจริง |
| `externalId` | – | เลขที่ใบเสร็จฝั่ง POS ไว้ตรวจสอบย้อนกลับ (echo กลับใน response) |

- ราคา: ถ้า POS ส่ง `price` มา ใช้ราคานั้น (รองรับโปรโมชั่น/ส่วนลดของร้าน) — ไม่ส่งใช้ราคาแค็ตตาล็อก
- บิลที่**ไม่มีข้อมูลสมาชิก** (ลูกค้าทั่วไป) จะได้ `{"recorded":false,"reason":"member_not_found"}` —
  ไม่ใช่ error: ระบบเก็บเฉพาะประวัติของสมาชิก ส่งทุกบิลมาได้เลยไม่ต้องกรองเอง

### Response (บันทึกสำเร็จ)

```json
{
  "recorded": true,
  "purchaseId": "...",
  "externalId": "RCPT-2026-08-0042",
  "member": { "id": "...", "displayName": "คุณเมย์" },
  "total": 65,
  "pointsEarned": 6,
  "newPointsBalance": 118
}
```

POS โชว์ `pointsEarned` / `newPointsBalance` บนสลิปได้เลย

## 4. จับคู่สินค้าล่วงหน้า (ทางเลือก)

ให้แม่นตั้งแต่วันแรก: หลังบ้าน → แท็บ **สินค้า** → ใส่ **Barcode/SKU** ให้สินค้าที่มีอยู่
สินค้าที่ barcode ตรงจะใช้ตัวตนเดิม (ประวัติ/คำแนะนำต่อเนื่อง) ไม่สร้างซ้ำ

## รูปแบบการต่อที่พบบ่อย

| POS ของร้าน | วิธีต่อ |
|---|---|
| POS cloud ที่มี webhook (Loyverse, StoreHub, Ocha ฯลฯ) | ตั้ง webhook ปิดบิล → middleware แปลง payload → `POST /pos/sales` |
| POS ที่เขียน plugin ได้ | เรียก `POST /pos/sales` ตรงจากตอนปิดบิล |
| POS เก่า/ออฟไลน์ที่ export ได้ | สคริปต์อ่านไฟล์ export (CSV) แล้ววนยิง `POST /pos/sales` ท้ายวัน |

ความปลอดภัย: key ผูกต่อสาขา เพิกถอน/ปิดชั่วคราวได้จากหลังบ้าน, เก็บเป็น sha256 ฝั่งเซิร์ฟเวอร์,
มี `lastUsedAt` ให้เช็คว่าสาขาไหนยังส่งอยู่
